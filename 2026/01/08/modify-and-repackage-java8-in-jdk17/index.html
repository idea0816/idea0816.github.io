How to Modify and Repackage a Java 8 JAR in a JDK 17 Environment

Posted by 曉羽 on Thursday, January 8, 2026

在維護舊有的 Java 專案時，經常會遇到一個尷尬的情況：手邊只有最新的 JDK（如 JDK 17），但目標環境卻運行在 Java 8 上。最近我遇到需要修改一個名為 rcmd.jar 的舊檔案，並調整其中的 com/vdnvn/SyncOrg.java 邏輯 。

紀錄了一下如何在不降級 JDK 的情況下，確保編譯出的檔案能相容於舊版環境。

準備工作

在開始之前，先確保目錄結構符合 Java 的 Package 規範。以這次修改的 SyncOrg.java 為例，檔案結構應如下：

根目錄：放置 rcmd.jar。 原始碼路徑：com/vdnvn/SyncOrg.java 。

Project_Folder/
├── rcmd.jar                # 原始的 JAR 檔
└── com/vdnvn/SyncOrg.class    # 修改後的原始碼

1. 使用 JDK 17 編譯相容於 Java 8 的類別 這是最關鍵的一步。如果直接執行 javac，產生的 .class 檔版本會過高（Java 17 為 version 61），導致 Java 8 環境出現 UnsupportedClassVersionError。

我們需要使用 –release 8 參數，這會同時檢查語法相容性與 API 可用性：

在根目錄執行，並將原本的 jar 加入 classpath 以便編譯

javac --release 8 -cp rcmd.jar com/vdnvn/SyncOrg.java

  • release 8：確保輸出的位元碼（Bytecode）版本為 52 (Java 8)。

  • cp rcmd.jar：讓編譯器能找到該檔案引用的其他類別（例如同套件內的 AD.class 或 B64Encoder.class） 。

2. 驗證位元碼版本 (Mac/Linux) 編譯完成後，在將 .class 壓回 JAR 之前，建議先確認版本是否正確。在 macOS 或 Linux (zsh) 環境下，可以使用以下指令：

javap -v com/vdnvn/SyncOrg.class | grep major

在 Windows 環境下，可以使用以下指令：

javap -v com/vdnvn/SyncOrg.class | findstr major

預期輸出：

major version: 52

這代表該檔案已成功編譯為 Java 8 格式。

3. 將修改後的檔案更新回 JAR 確認版本無誤後，我們使用 jar 指令的 u (update) 功能，將新的 .class 檔覆蓋掉 rcmd.jar 裡舊有的檔案 ：

jar uf rcmd.jar com/vdnvn/SyncOrg.class

這個指令會根據路徑 com/vdnvn/SyncOrg.class 自動尋找並替換 JAR 包內對應位置的檔案 。

注意事項總結 - 語法限制：在修改代碼時，即便使用 JDK 17 開啟，也不能使用 Java 8 之後才有的語法（例如 var 或 Lambda 的新特性）。

  • 路徑一致性：執行 jar uf 時，必須在 com 資料夾的上一層執行，否則 JAR 內的目錄結構會出錯。

  • 系統指令差異：在 Windows 上過濾字串請用 findstr，而 Mac/Linux 則使用 grep。

透過 –release 參數，我們可以很優雅地在現代開發環境中維護遺留系統（Legacy System）。希望這篇紀錄也能幫到正在處理舊版 JAR 檔的你！
